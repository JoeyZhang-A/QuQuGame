# 02 · 决策与性格

决策层把状态翻译成动作。这一层决定蛐蛐"看起来什么脾气"。

## 1. 性格五维

全部是倾向，不是强度。没有"攻击力"这种直接换算胜负的东西。

| 参数 | 范围 | 含义 | 影响的动作 |
|---|---|---|---|
| `A` 攻击 | 0..1 | 主不主动开打 | `bite` `approach` ↑，`hold` `retreat` ↓ |
| `R` 冒险 | 0..1 | 敢不敢绕侧面、敢不敢扑 | `flank` `bite` ↑，`retreat` ↓ |
| `E` 耐力 | 0..1 | 愿不愿意磨 | `hold` ↑，`bite` ↓，角力有效力 ↑ |
| `S` 应激 | -1..1 | 急了之后发狠还是缩 | 压力 >60 时分流 |
| `P` 换招 | 0..1 | 动作切换频率。0 极黏、1 极碎 | 重复惩罚系数 |

`S` 是唯一带符号的参数。`S > 0` 急了更凶，`S < 0` 急了更缩。

`E` 有双重作用：既影响打分，也影响角力有效力（见 01 第 5.3 节）。这是"耐力型靠磨赢"的唯一实现通道。

## 2. 特征

每拍决策前计算 7 个特征，全部为 0..1 的定点整数（乘 100）。

| 特征 | 计算 |
|---|---|
| `near` | 曼哈顿距离 1 → 100；2 → 50；3 及以上 → 0 |
| `far` | 距离 3 及以上 → 100；2 → 50；1 → 0 |
| `face` | 对手落在朝向 90° 扇区内 → 100，否则 0 |
| `sta` | `stamina` |
| `pre` | `pressure` |
| `sup` | `pressure > 60 且 S > 0` → 100，否则 0 |
| `sdn` | `pressure > 60 且 S < 0` → 100，否则 0 |

`stamina` 与 `pressure` 本身就在 0..100，直接当特征值用。

`face` 用 01 第 5.1 节的 `dot > 0` 判定，不另算角度。

## 3. 打分

每个动作算一个总分，取最高。分数是整数，量级大致 0..1500。

```
score[a] = base[a]
         + (w_near[a] * near + w_far[a] * far + w_face[a] * face) / 100
         + (w_sta[a] * sta + w_pre[a] * pre) / 100
         + (w_sup[a] * sup + w_sdn[a] * sdn) / 100
         + (p_A[a] * A + p_R[a] * R + p_E[a] * E) * 100
         - repeat_penalty[a] * P        // 仅当本动作 == 上一拍动作
         - hold_chain_penalty           // 仅对 hold 生效
```

`A R E` 是 0..1，乘 100 后转成整数分量。全部整数除法，先乘后除，不产生中间浮点。

### 3.1 特征权重

| 动作 | base | near | far | face | sta | pre | sup | sdn |
|---|---|---|---|---|---|---|---|---|
| `hold` | 200 | +250 | +100 | 0 | +200 | -250 | -150 | +200 |
| `retreat` | 150 | -300 | +100 | 0 | -600 | 0 | -200 | +350 |
| `approach` | 200 | -250 | +500 | 0 | 0 | 0 | +100 | -150 |
| `flank` | 200 | +150 | -100 | +200 | 0 | 0 | 0 | +100 |
| `bite` | 100 | +600 | -400 | +350 | +250 | 0 | +400 | -300 |

### 3.2 性格权重

| 动作 | A 攻击 | R 冒险 | E 耐力 |
|---|---|---|---|
| `hold` | -250 | -100 | +350 |
| `retreat` | -150 | -350 | +50 |
| `approach` | +300 | +50 | -100 |
| `flank` | -100 | +350 | +50 |
| `bite` | +400 | +250 | -250 |

### 3.3 重复惩罚

`repeat_penalty` 只在"本拍候选动作等于上一拍动作"时生效：

| 动作 | 惩罚基数 |
|---|---|
| `hold` | 120 |
| `retreat` | 200 |
| `approach` | 150 |
| `flank` | 250 |
| `bite` | 300 |

实际扣分 = `惩罚基数 * P / 100`。

`P` 高的人几乎不扣（爱换招），`P` 低的人扣满（爱重复）。这是"闷"与"碎"的唯一实现通道。

### 3.4 防死锁

两条硬规则，缺一不可。

**僵持连坐**：`consec_hold >= 3` 时，`hold` 额外扣 `(consec_hold - 2) * 120`。
连续僵持第 3 拍扣 120，第 4 拍扣 240，以此类推。保证两只高耐力虫不会对站到终局。

**换招上限**：连续 6 拍做同一动作后，该动作本拍分数强制置 `-999999`。这是兜底，正常参数下不应触发。

### 3.5 平局打破

分数相同时按固定优先级取，严禁依赖遍历顺序：

```
bite > approach > flank > hold > retreat
```

实现时把候选动作按此顺序存入 `const ACTION_ORDER`，`argmax` 用 `>` 而非 `>=` 比较即可。

## 4. 决策伪代码

```
func decide(self, opp) -> String:
    if locked:                      # 角力锁定或硬直
        return "hold"

    feat = compute_features(self, opp)
    best = ACTION_ORDER[0]
    best_score = -1000000

    for a in ACTION_ORDER:
        s = score(a, feat, self.params)
        if a == self.last_action:
            s -= REPEAT_PENALTY[a] * self.params.P / 100
        if a == "hold" and self.consec_hold >= 3:
            s -= (self.consec_hold - 2) * 120
        if a == self.same_action_chain and self.chain >= 6:
            s = -999999
        if s > best_score:
            best_score = s
            best = a

    return best
```

`compute_features` 与 `score` 都必须是纯函数：只读状态，不改状态，不读写任何全局。

## 5. 五只蛐蛐

参数是初始值，需靠自博弈调。但**参数之间必须是现在这个关系**，调数值不许改关系。

| 代号 | 显示名 | A | R | E | S | P | 唯一主导 | 预期行为画像 |
|---|---|---|---|---|---|---|---|---|
| `scale` | 老秤砣 | 0.20 | 0.15 | **0.90** | -0.90 | 0.25 | E 最高 | 僵持多，被打就守，靠角力磨赢 |
| `rush` | 急先锋 | 0.75 | 0.60 | 0.20 | +0.40 | **0.85** | P 最高 | 换招极碎，一刻不停变，容易扑空 |
| `abacus` | 算盘精 | 0.40 | **0.90** | 0.45 | 0.00 | 0.40 | R 最高 | 绕行占比最高，极少正面顶 |
| `stew` | 闷葫芦 | 0.35 | 0.10 | 0.75 | -0.20 | **0.05** | P 最低 | 极黏，动作成块，反复做同一件事 |
| `fool` | 愣头青 | **0.85** | 0.15 | 0.10 | +0.90 | 0.30 | A 最高 | 直线猛冲不绕，体力掉得最快 |

**每只虫只有一个主导维度，且这五个维度互不重叠。** 这不是巧合，是人工测试的标准答案来源（见 `05-verification.md` 3.5）。

调参数时，主导维度不许换人。可以把 0.90 调到 0.85，但不能让 `stew` 的 `E` 超过 `scale`。

设计意图，实现时不要"优化"掉：

- `scale` 与 `stew` 都是慢型，区别在 `P`（0.25 vs 0.05）和 `S`（-0.90 vs -0.20）。前者守得更死，后者对压力几乎无反应。这两只是全组最容易被测试者混淆的一对，数据上必须分开。
- `rush` 与 `fool` 都是主动型，区别在 `P`（0.85 vs 0.30）和 `R`（0.60 vs 0.15）。前者碎、会绕；后者成块、直线。
- `abacus` 是唯一 `R` 接近 0.9 的，`flank` 占比必须显著高于其他四只，否则说明 `flank` 权重没生效。
- `S` 是隐藏维度，60 秒内不一定显现。它不作为人工测试的标准答案，只在 `Q1` 的开放描述里自然出现。

## 6. 参数与行为的对应关系（调参用）

改参数时的因果链，别乱拧：

| 想让它更… | 拧这个 | 侧面效果 |
|---|---|---|
| 主动 | `A` ↑ | `retreat` 变少，容易被打 |
| 爱绕 | `R` ↑ | `bite` 也会变多（`R` 同时抬 `bite`） |
| 能磨 | `E` ↑ | `bite` 变少，但角力赢面变大 |
| 急了更凶 | `S` ↑ | 只在 `pressure > 60` 后生效 |
| 动作更碎 | `P` ↑ | 重复惩罚变轻，序列更杂 |
| 动作更黏 | `P` ↓ | 会出现长段重复，注意别撞上 6 拍上限 |

`P` 调到 0.05 以下时，`hold` 会连续触发僵持连坐。这不是 bug，是设计。

## 7. 禁止事项

- 不得加入随机扰动。行为差异必须来自参数与状态。
- 不得让决策读取表现层的任何内容（动画进度、帧数、镜头）。
- 不得为"看起来更自然"加入随机延迟、随机朝向。
- 不得跨拍记住对手的动作做预测。本版不做预判，读起来才干净。

第 4 条是刻意的：加入预判会让行为变复杂、可读性下降，而可读性正是要验证的东西。V2 再考虑。
