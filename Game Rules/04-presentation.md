# 04 · 表现层

表现层只做一件事：**让规则层的行为被看见**。

不做美术、不做音效、不做镜头运动。全部用几何图形。

判定原则：如果一个视觉元素不能让玩家更好地读出"它要干什么"或"它紧不紧张"，就删掉。

## 1. 场景结构

```
main.tscn
└── Main (Node2D)              main.gd
    ├── Arena (Node2D)         arena_view.gd     场地网格
    ├── Crickets (Node2D)
    │   ├── A (Node2D)         cricket_view.gd
    │   └── B (Node2D)         cricket_view.gd
    └── HUD (CanvasLayer)      hud.gd            仅 --hud=on 时可见
```

窗口 1280×720，固定尺寸，不可缩放。固定全景，**不跟镜、不缩放**。

镜头一跟，相对位置就读不出来了。可读性优先于电影感。

## 2. 场地

| 项 | 值 |
|---|---|
| 槽位尺寸 | 120 × 120 px |
| 场地总尺寸 | 600 × 360 px |
| 场地左上角 | (340, 180) |
| 槽位坐标换算 | `px = 340 + x*120 + 60`，`py = 180 + y*120 + 60`（得槽中心） |
| 背景 | `#1C1917` |
| 槽线 | `#2E2A26`，1px |
| 中心槽 | 描边 `#3D3833`，2px，仅此而已，不加高亮 |

中心槽只做极轻的视觉标记，因为它参与超时判分。不要做成"要抢的目标点"，那会诱导玩家看战略而不是看虫。

## 3. 蛐蛐外形

全部是 `_draw()` 画的图形，不用图片资源。

| 部件 | 形状 | 说明 |
|---|---|---|
| 身体 | 椭圆 40×24 | 先手 `#4A4038`，后手 `#2E2822` |
| 描边 | 1.5px | 先手 `#C39A5E`，后手 `#6B563C` |
| 触角 | 2 条线段，长 26 | 从身体前端伸出，基准角度 ±35° |
| 上颚 | 2 条短线段，长 8 | 仅在 `bite` 时可见 |
| 腿 | 4 条短线，长 10 | 可选，若实现成本高可省略 |

朝向由椭圆长轴方向表达。8 向朝向映射到 8 个旋转角度，用 `rotation` 或手算顶点都行。

两只虫靠**明暗**区分先后手，不靠色相。用颜色区分会让人下意识给颜色赋予性格。

## 4. 起手可视化

这是整套设计的核心。没有这个，玩家只能看到虫在动，读不出意图。

| 动作 | 起手表现 | 起手时长 |
|---|---|---|
| `hold` | 原地，触角前后轻摆（振幅 3px） | 无 |
| `retreat` | 身体后倾 10°，后腿绷直，整体后移 6px | 100 ms |
| `approach` | 身体前倾 8°，前腿抬起，整体前移 6px | 180 ms |
| `flank` | 身体先转向侧移方向，抬起外侧腿 | 240 ms |
| `bite` | **身体压低 30%，触角收拢至 ±10°，上颚张开** | 280 ms |

`bite` 的起手必须最醒目。它是最危险的动作，也是玩家最需要提前看到的一个。

位移本身用插值：起手结束时开始移动，生效阶段内走完 120px，`ease_out`。

## 5. 结果表现

| 事件 | 视觉 |
|---|---|
| 咬合命中 | 双方各前冲 10px 后弹回，同时轻微缩放（1.0→1.06→1.0），持续 120ms |
| 压制 | 守方被推开 1 槽，用 200ms 插值，带 `ease_out` |
| 被反制 | 攻方被推回 1 槽，同上 |
| 僵平 | 双方同时轻微抖动 60ms |
| `whiff` | 前冲过头 18px，然后**定格 200ms** 才回位 |

`whiff` 的定格是惩罚的视觉化。别做顺滑动画，要让它看起来"扑了个空、愣在那"。这是性格坑自己最容易被看见的一刻。

## 6. 压力外化（A 版，无条）

三档质变，不是连续渐变。连续渐变读不出"它快崩了"。

| 压力区间 | 触角频率 | 身体起伏 | 附加 |
|---|---|---|---|
| 0–59 稳 | 1.0 Hz | 0 → 3 px，2 Hz 正弦 | 无 |
| 60–84 紧 | 3.0 Hz | 3 → 5 px | 叠加 12 Hz / 1px 高频抖 |
| 85–100 崩 | 5.0 Hz | **起伏归零（僵住）** | 只有高频抖，整体缩放 0.97 |

关键点：进入 85 档时**起伏突然停止**。一只原本在轻微喘的虫突然不动了、只剩高频抖——这个质变比任何数值条都更能传达"要崩了"。

后撤步幅：`pressure > 60` 时位移距离 ×0.7，读起来像"腿软"。

四个通道：触角频率、身体起伏、高频抖、步幅。少一个都会削弱可读性，但先按四个做，测完再砍。

## 7. HUD（B 版）

`--hud=on` 时出现，`off` 时整个 `HUD` 节点隐藏。

| 项 | 值 |
|---|---|
| 位置 | 屏幕顶部中央，y = 40，宽度 160，高度 8 |
| 刻度 | **无**。不画数字、不画分割线 |
| 分段 | 3 段（0–59 / 60–84 / 85–100），颜色 `#6B7F5C` / `#B8863B` / `#8E3B32` |
| 常态 | alpha 0.25，只显示当前段填充 |
| 跨段 | alpha 1.0，边框闪 200ms，然后回到 0.25 |
| 归属 | 两条，上为 A 虫，下为 B 虫 |

**不显示体力。** 体力做成条会诱导玩家算账，注意力从虫身上转到数字上。

压力条本身也不显示数值。玩家知道"到第二段了"，算不出"还差 8 点"。

## 8. 启动参数

命令行参数在 `main.gd` 的 `_ready()` 里解析，用 `OS.get_cmdline_user_args()`（`--` 之后的部分）。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--hud=on\|off` | `off` | 压力条开关 |
| `--match=id1,id2` | `scale,rush` | 指定对阵 |
| `--speed=1\|2\|4` | `1` | 播放松紧，仅影响表现层，不影响逻辑 |
| `--auto-quit=1` | `0` | 打完后自动退出，用于批处理 |

示例：

```
"D:\Godot4\Godot_v4.7.2-stable_win64_console.exe" --path "D:\workspace\QUQU FIGHT2" -- --match=rush,abacus --hud=on
```

## 9. 表现层与逻辑层的界限

表现层读逻辑层的状态，只读不写。

允许：
- 每拍开始读一次逻辑快照
- 在 450ms 内做插值、动画、抖动

禁止：
- 回写任何逻辑状态
- 用动画时长影响 tick 推进
- 在 `_process(delta)` 里推进逻辑

逻辑推进由独立的计时器或固定累加器驱动，`delta` 只服务插值。

## 10. 明确不做

- 纹理、精灵、骨骼动画
- 音效与音乐
- 镜头推拉、跟拍、慢镜
- 粒子、拖影、屏幕震动
- 血条、伤害数字、飘字
- 蛐蛐名字、等级、胜率展示（会泄题）

这十条里任何一条被"顺手加上"，都会削弱 Demo 1 的验证效力。测试阶段画面越素，读出来的越可信。
