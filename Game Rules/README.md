# 斗蛐蛐 Demo 1 · 总览

一个可运行的观战原型。两只蛐蛐按固定拍子自动对打，玩家只能看，不能操作。

Demo 1 只回答一个问题：**玩家看完之后，能不能用自己的话说出这只蛐蛐什么脾气。**
回答不了，整个项目不成立。所以这一版里所有不服务于这个问题的东西全部不做。

## 交付物

一个 Godot 4 项目，具备三个可运行入口：

1. 单局观战：双击运行，看两只蛐蛐打一场（60 秒）
2. 批量自博弈：命令行跑 N 局，输出结构化日志与分布统计
3. HUD 两版：`--hud=off`（无条）/ `--hud=on`（三段压力条），用于对照测试

## 硬约束

违反任意一条即为错误实现，不接受"后面再改"。

1. **纯旁观**。没有任何输入。不接键盘、不接鼠标、不接手柄。
2. **逻辑层零依赖**。规则核心不继承 `Node`、不用 `CharacterBody2D`、不用物理引擎、不碰 `Input`、不碰渲染。纯 RefCounted 类，headless 可跑。
3. **全整数化**。位置、体力、压力、朝向全部整数。打分结果乘 1000 取整后再比较。禁止用浮点数参与 state 存储。
4. **不用随机数决定行为**。行为完全由参数与状态推导。随机只允许出现在初始化，且必须走种子化 `RandomNumberGenerator`。初始位置本版固定，连初始化随机都不需要。
5. **不显示体力数字，不显示体力条**。压力条仅在 `--hud=on` 时出现。
6. **不做**：养成系统、AI 叙事、复盘 UI、生涯记录、绰号、音效、美术资源、多场连战。

## 验收总门槛

三条全过才算 Demo 1 成立：

1. 同一只虫对 5 个不同对手，动作分布平均 L1 距离 ≤ 0.25（性格不被对手带跑）
2. 不同虫两两之间，动作分布 L1 距离 ≥ 0.30（性格互相可分）
3. 人工测试：A 组 5 人中至少 3 人，能正确说出看过的一半以上蛐蛐的核心倾向

第 3 条是唯一真正的验收。前两条不过就别去测人。

## 实现顺序的铁律

先日志，再画面。

事件日志是复盘、统计、验收的唯一数据源。所有验证都从日志里读。
画面只是日志的另一种渲染方式。顺序反了，后面全是补丁。
