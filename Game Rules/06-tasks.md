# 06 · 执行任务

12 个任务，按序做。每个任务有独立可验证的产出，做完立刻验，不要攒到最后。

前 10 个是 headless 的。**画面在 T11 才开始。** 这条顺序不许调整。

单测不单独排期，跟着 T2–T7 一起写。哪个任务交付，哪个任务的单测必须同时绿。

---

## T1 项目骨架

**目标**：Godot 项目能起来，三份配置能加载并校验。

产出：
- `project.godot`，主场景指向 `scenes/main.tscn`
- `data/` 下三份 JSON
- `src/core/config.gd`：加载 + 校验 + 暴露只读结构
- `scenes/main.tscn`：空节点，能启动

验收：
```
"...console.exe" --headless --path "D:\workspace\QUQU FIGHT2" --quit
```
退出码 0，无报错。

校验必须硬失败：`A=1.5` 这种越界值要报错退出，不许静默钳制。钳制会让调参时的错误藏起来。

## T2 规则核心：状态与移动

**目标**：蛐蛐状态、tick 推进、槽位移动能跑。

产出：
- `src/core/cricket.gd`：`extends RefCounted`，持 position / facing / stamina / pressure / last_action / consec_hold
- `src/core/rules.gd`：移动合法性、边界钳制、朝向计算
- `src/core/match.gd`：tick 主循环骨架，动作先固定为 `hold`
- `tests/test_rules.gd`：单测 1–6

验收：单测 1–6 全绿。跑 133 拍，位置不变、体力封顶 100。

**自查**：`src/core/` 下搜 `extends Node` 必须为空。

## T3 动作状态机

**目标**：5 个动作按三阶段执行，位移生效。

产出：
- 动作阶段推进（windup / active / recover）
- 三种位移语义 `near` / `away` / `side` 解析成具体坐标
- `flank` 侧移方向选择与退化逻辑

验收：单测 1、3、4、5、6 全过。
另加手工验证：`abacus` 对 `scale` 跑一场，日志里 `flank` 的 `to` 坐标确实在 y 轴方向变化，不是 x。

---

## T4 咬合、角力、互咬

**目标**：整个咬合流程闭环。

产出：
- 命中判定（距离 + 朝向点积）
- `whiff` 分流与三种 `reason`
- 角力结算，占一整拍，双方锁定
- 角力后的硬直
- 双方同拍互咬（规则 5.4），不进角力不锁定
- `tests/test_grapple.gd`：单测 7–17

验收：单测 7–17 全过。

**重点**：角力那一拍，日志里不能有任何 `type == "tick"` 记录，只有一条 `grapple`。这条错了说明锁定没做对，后面的分布统计全是脏数据。

互咬那一拍相反，两条 `tick` 记录都要有，`action` 都是 `bite`，另加一条 `clash`。

## T5 胜负判定

**目标**：四种结束方式都能正确触发。

产出：判定函数 + 优先级顺序

验收：单测 18–22 全过。

另加三个手工构造的场景（临时改配置或直接构造状态）：
- 体力打成 0 → `stamina_zero`
- 体力 15 连撤两拍 → `flee`
- 打满 133 拍 → `timeout`

## T6 决策打分

**目标**：7 特征 + 权重矩阵 + 性格项 + 两条防死锁，输出动作。

产出：
- `src/core/decision.gd`：`compute_features` 和 `score` 为纯函数
- 重复惩罚 `repeat_penalty * P / 100`
- 僵持连坐
- 6 拍兜底
- 平局按 `action_order`
- `tests/test_decision.gd`：单测 23–28

验收：单测 23–28 全过。

再加一步人工核对：写个临时脚本，固定一个状态，把 5 个动作的分数打印出来，与 `weights.json` 手算对一遍。差 1 分以上就是整数除法写错了。

这一步别省。整数除法的取整方向错了，整套调参都会失准，而现象很隐蔽——行为看起来"差不多对"。

**目标**：日志完整、可 `grep`、可 `diff`。

验收：
1. 一场日志行数 = 头 1 + 决策记录 + 关键事件 + 尾 1

3. `grep '"type":"grapple"'` 能捞出全部角力

**目标**：五只虫参数读进来，行为分布出现差异，且过数据门槛。

## 卡住时的判断顺序

1. headless 跑不起来 → 查 `src/core/` 有没有混进 `Node` 或场景引用
2. 日志不确定 → 查随机源、查浮点、查时间依赖
3. 行为没差异 → 先验证 `weights.json` 真的被读了（改一个值看分数变不变）
4. 差异太大像乱走 → 调低 `sta` / `pre` 权重，让性格权重占比更大
5. 数据好但人看不出 → 问题在表现层，不在规则层

顺序不许跳。第 1 条不修，后面全是白干。
